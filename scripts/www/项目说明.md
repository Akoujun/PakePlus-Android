# 情侣运动金币 V3.6（当前基线）项目说明

## 1. 版本定位

`V3.6` 是在 `V3.5` 基础上的"透支管理独立模块 + 上周开销剩余展示"版本。

本次目标：

- 新增独立的"透支管理"标签页，支持人工管理透支项
- 每笔透支项支持进度条展示还款进度
- 支持手动输入冲还金额，多笔冲还汇总
- 总览页新增"上周开销剩余"卡片，展示计算明细
- 隐藏原有自动抵扣透支余额卡片（保留代码）

## 2. 核心业务规则（V3.6）

### 2.1 周可消费池

- 本周初始可用金 = 上周新赚金币（优先使用手工修正值）
- 本周可消费余额 = 本周初始可用金 - 本周可消费池花销
- 本周新赚金币不立即可花

### 2.2 家庭储备池

- 只统计严格早于本周且已结束周的结余转入
- 当前显示余额 = `manualBaseBalance + 自动转入累计 - 家庭储备池花销`
- 当前周不直接进入家庭储备池

### 2.3 透支池（自动抵扣系统，保留）

- 透支录入支持：总金额 + 已抵扣金额
- 手工已抵扣金额先计入
- 周结余自动抵扣在其后叠加
- 当前透支余额 = 所有透支记录剩余未还金额之和
- 支持手工补记抵扣：将补记金额按时间顺序分配到未还清透支记录上，直接减少当前透支余额

### 2.4 透支管理模块（V3.6 新增）

- 独立于自动抵扣系统，支持人工管理
- 每笔透支项包含：项目名、开始时间、初始金额、已还金额
- 支持多笔冲还记录，汇总成最新已还金额
- 进度条展示还款百分比
- 已还清透支项沉底显示，待还款项优先展示
- 总透支剩余金额实时统计

### 2.5 周结余自动抵扣顺序

每个已结束周：

1. 先计算周结余 `max(0, 上周可用金 - 本周花销)`
2. 先抵扣透支
3. 剩余部分进入家庭储备池

### 2.6 本周打卡奖励规则（V3.2+）

- 每个打卡项包含：名称、目标次数、奖励金币
- 当 `doneCount >= targetCount` 视为达标
- 达标后奖励金币并入本周新赚金币，与运动记录金币共同汇总
- 本周新赚金币自动汇总：`运动记录金币 + 打卡奖励金币`

### 2.6 打卡周格子规则（V3.4）

- 每个打卡卡片展示 7 格周视图：`周一 -> 周日`
- 点击 `+1` 记一次打卡，并点亮对应“当天星期格子”
- 点击 `-1` 回退最近一次打卡记录（与次数保持一致）
- 同一个打卡项在同一自然日最多只能成功打卡一次
- 新周开始后，本周打卡数据独立重建，格子回到初始态
- 额外周隔离保护：非当前 `weekKey` 的打卡日志不会参与当前周展示

### 2.7 固定打卡项规则（V3.4）

- 创建打卡项时可选择：`仅本周` / `固定打卡项`
- 固定打卡项会在每周一自动生成新的本周打卡卡片
- 固定打卡项每周都会重置：次数、完成状态、奖励发放状态、打卡日志
- 中止固定打卡项后：
  - 当前周对应固定卡片会被移除
  - 后续新周不再自动生成

## 3. 已实现功能（V3.5）

### 3.1 运动类型管理（延续 V3.1）

- 类型卡片可编辑，进入编辑态可滚动聚焦
- 保存后更新该类型
- 历史运动记录不回写

### 3.2 数据修正（延续 V3.1）

- 上周新赚金币修正（`manualTotalCoins`）
- 家庭储备池基线修正（`manualBaseBalance`）
- 保存后触发全局账务重建

### 3.3 透支录入（延续 V3.1 / V3.5）

- 支持“已抵扣金额”（`manualRepaidAmount`）
- 校验：`已抵扣金额 <= 透支总金额`
- 自动汇总当前透支余额
- 支持“手工补记抵扣”，用于人工确认后直接减少当前透支余额

### 3.4 本周打卡页（V3.2+）

- 新增标签页：`本周打卡`
- 支持新增打卡项（名称/目标次数/奖励金币）
- 支持 `+1 / -1 / 删除` 操作
- 达标触发礼花效果

### 3.5 固定打卡项（V3.4）

- 支持将打卡项保存为固定打卡项
- 固定打卡项会在当前周立即生成卡片，并在后续每周自动生成
- 固定打卡项卡片展示 `固定` 标记
- 支持 `中止固定` 操作

### 3.6 打卡显示稳定性修复（V3.3）

- 修复“存在数据但卡片不显示”的渲染中断问题
- 打卡卡片渲染改为“模板优先 + 纯 JS 降级兜底”
- 解决脚本执行时序导致的渲染失败问题

### 3.7 全局人员命名调整（V3.3）

- `我` -> `嘟嘟`
- `配偶` -> `皮屁`
- 覆盖录入端与记录展示端的人名映射

## 8. 已知限制

- 透支记录暂不支持编辑/删除
- 自动抵扣记录是重建结果，不支持手工改写
- 手工补记抵扣暂不支持编辑/删除
- 未提供按周账务调试面板
- 未接入自动化测试
- `app.js` 仍为单文件脚本

## 9. 下一步建议（V3.5 后续）

建议优先顺序：

1. 透支记录编辑/删除能力
2. 手工补记抵扣记录查看与撤销
3. 打卡记录编辑能力（补录日期、纠错）
4. 账务调试面板（每周可见：手工值、自动值、抵扣值）
5. 核心回归测试（跨周、透支、手工修正、打卡奖励联动）
